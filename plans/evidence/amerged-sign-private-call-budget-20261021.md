# amerged Sign private runtime call verification — 2026-10-21

Status: source and local boundary verification. Deployment, hosted CPU use and real invitation delivery require the separate Dev acceptance run. No provider or customer-data operations were performed for these measurements.

The OMH customer dispatch policy permits ten subrequests per HTTP request and 50 ms of CPU. A SQL query and a SQL transaction each consume one private database call. Parallel queries remain separate calls. Private file download consumes two calls; upload consumes three. This change preserves those limits.

The SQL tests apply every committed application migration to PGlite and execute the actual parameterized Drizzle queries through the OMH database binding. The creation test checks the real private-client wire paths; recipient file storage is an external boundary with the same two-call read/three-call upload budget. Neither fixture provides Cloudflare CPU measurements or hosted network evidence.

Independent disposable PostgreSQL 18 checks also executed eight owner projection/authorization cases at one query each, successful creation and a concurrent lifecycle-change rollback at two transaction calls each. A two-connection PostgreSQL experiment reproduced the audit-only deletion race: a single locking CTE could use an old statement snapshot and register a manifest after deletion intent. Locking the envelope in the first transaction statement and testing authority in the next statement admitted no manifest. The application now uses this order without extra private calls. PGlite does not substitute for PostgreSQL row-lock concurrency verification.

The retained invariants are owner/recipient isolation, parameterized inputs, an immutable PDF locator manifest before upload, inactive signer links until accepted invitation delivery, atomic command receipts, and fresh lifecycle/ownership/token/deletion checks before final activation. Durable `envelope.deletion_started` intent closes reads and new manifests before erasure inventories keys. Failed erasure keeps the actual prior status and the same retryable intent. A late immutable upload to an erased locator cannot resurrect the file. SQL transactions do not span file or mail awaits.

Dependency review reduced the actual audit from 63 findings to two development-tool findings, with no production findings after compatible patch updates (Hono 4.13.11, Vite 8.2.4, Vitest 4.1.11). Remaining findings are obsolete Drizzle's pinned esbuild loader ([GHSA-67mh-4wv8-2f99](https://github.com/evanw/esbuild/security/advisories/GHSA-67mh-4wv8-2f99)) and semantic-release's braces dependency, for which the advisory reports no patched release ([GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm)). No advisory suppression, broad major upgrade or dependency-age exception was added.
